# town-next: ビューア UI 設計（案）

town-next（`cmd/town-next` / `internal/next` / 8788）用のビューアの設計。**実装はまだしない**。
今のタウン（8787 / `web/`）・`internal/world` の既存コード・今のタウン側の Go には触れない。
`web/` の既存スマホ用コードは参考にせず、新規に作る（オーナー方針）。

前提にした文書:
- [town-next-usecases.md](town-next-usecases.md) — 大原則（エージェントと人間を同じ扱い・同じ API・同じ画面）、柱 5 本、暮らしの具体例、ネットは閲覧自由・書き込み禁止
- [ios-safari-viewport.md](ios-safari-viewport.md) — iPhone のフォーカスズーム・キーボード・ビューポート（出典 [S1]〜[S15] はこの文書の番号）
- [town-next.md](town-next.md) — 今ある API・権限・未対応

ユースケースはまだ「合意中」。この文書も、それに合わせて変わる前提の案。

## 0. 守ること（この設計全体の判定基準）

1. **画面はひとつ。** 人間もエージェントも同じビューア・同じ URL・同じ表示。「AI 用の画面」「AI 用の API」は作らない。
2. **操作はすべて既存の HTTP API（NIP-98）に落ちる。** ビューアのボタンは API を 1 回叩くだけの薄い層。エージェントは同じ API をツールから叩く。ボタンにしかできないこと、ツールにしかできないことを作らない。
3. **地図が主役。** どの画面サイズでも、どの操作中でも、地図の大きさは変えない。
4. **観測していないものは表示しない。** API に無い値（相手の状態・持ち物など）をビューア側で作り出さない。無いものは出さない。

## 1. 画面構成

### 1.1 スマホ縦（基準: 幅 360〜430 CSS px）

```
┌──────────────────────────┐
│ 地図（画面高の 58%）        │ ← 自キャラ中心。ドラッグでパン
│                  ┌────┐  │
│                  │ミニ│  │ ← ミニマップは地図の右上に重ねる
│                  └────┘  │
│          ⚡(自分)          │
│                    [◎]   │ ← 「自分に戻る」ボタン（パン後のみ表示）
├──────────────────────────┤
│ 知らせ 1 行（未読があるとき）│ ← タップで知らせ一覧
├──────────────────────────┤
│ チャット（最低 4 行）        │
│ …                        │
├──────────────────────────┤
│ [行動] [ 入力欄 16px+ ][送]│ ← 入力バー
└──────────────────────────┘
```

- **地図: 高さ `58svh` 固定**（下限 55%。文字サイズ段階で 55〜60% の間で決める。1.4）。
  - `svh` を使う理由: `svh/lvh/dvh` は Safari 15.4 以降で使え [S11][S8]、`dvh` はツールバーの出し入れで値が動く [S12]。地図の大きさを「何があっても変えない」ために、動かない `svh` で固定する。ページ全体は `100dvh`（ツールバーの出し入れの差分は下のチャット欄が吸収する）。
  - キーボードではどの単位も変わらない [S9][S12]。地図の大きさはキーボードに依存しない（2 章）。
- **タイル: 1 タイル 24 CSS px 以上**（既定 28px、文字サイズ段階で 24/28/32）。
  - 町は 58×20 タイル（`town-next.example.json` の `town` ルーム）。幅 390px・28px なら横 13〜14 タイルしか入らないので、**全体表示はしない**。自キャラを中心に描き、指ドラッグでパンする。
  - 自キャラが動くと中心に戻る（パン中は戻らない。[◎] で戻る）。ピンチは地図のズームにせずブラウザのズームに任せる（地図側でピンチを奪わない。WCAG 1.4.4 [S6]）。
- **ミニマップ: 地図の中に重ねる**（右上、地図幅の 30% 程度、半透明）。画面の行を別に使わない。タップでその場所へパン。小さな [×] で畳める。
  - ミニマップに出すのは `/world` のビューで見えているものだけ（見えないゾーンは塗らない）。
- **チャット: 最低 4 行**（文字サイズ「大」のときだけ下限 3 行）。新着で下に追従、上にスクロールすると追従を止めて「新着 n 件」ピルを出す。
- **入力バー:** 左に [行動] ボタン（3 章のシート）、中央に入力欄、右に送信。

### 1.2 PC（幅 1024 CSS px 以上）

```
┌──────────────────────────────┬───────────────┐
│ 地図（高さ 100%・幅 70%）      │ 知らせ          │
│                     ┌────┐   │───────────────│
│                     │ミニ│   │ チャット         │
│                     └────┘   │ （残り全部）      │
│                              │───────────────│
│                              │ [行動][入力][送] │
└──────────────────────────────┴───────────────┘
```

- 地図は左、幅 70%・高さ全部。タイルは 32px 既定（24 以上）。パン・中心追従はスマホと同じ。
- 右カラムに知らせ・チャット・入力バー。行動シートは右カラム内のポップオーバー。
- クリック = タップ、矢印キー/WASD で 1 タイル移動（`/move` を 1 回）。Enter でチャットへフォーカス。
- 幅 1023px 以下はスマホ縦のレイアウトを使う（横向きは未決 12）。

### 1.3 共通の部品

| 部品 | 中身 | データの出どころ |
|---|---|---|
| 地図 | ルーム・ゾーン・壁・家具・アクター | `GET /world`（`?auth=` で自分のビュー） |
| 名札 | 名前 + `rights.label`（`オーナー` / `家主` / `招待`、空なら無し） | 同上。**人間/AI の区別は出さない**（データに無い） |
| 知らせ | ノック・話しかけ・招待など | **未対応**（差分通知と留守中の保管が API に無い。5 章） |
| チャット | `/say` の発言 | `/world` のイベント |
| 行動シート | 今いる場所・近くの家具でできること（3 章） | 家具の `kind` と位置から決める |

### 1.4 文字サイズの段階

| 段階 | チャット本文 | 名札 | タイル | 地図の高さ | チャット最低行数 | 入力欄 |
|---|---|---|---|---|---|---|
| 小 | 14px | 11px | 24px | 60svh | 4 行 | **16px** |
| 中（既定） | 16px | 12px | 28px | 58svh | 4 行 | **16px** |
| 大 | 18px | 14px | 32px | 55svh | 3 行 | **18px** |

- **入力欄（`<input>` / `<textarea>` / `contenteditable` すべて）は使用フォントサイズ 16px 以上**。16px 未満だとフォーカス時に iPhone が自動ズームする [S1][S2]。`getComputedStyle(el).fontSize` をフォーカスされる要素そのものでテストする。`transform: scale()` で縮めない（使用サイズは変わらず見た目だけ小さくなる、と推測されている）。
- `maximum-scale=1` / `user-scalable=no` は**使わない**（自動ズームを隠すだけで、文字拡大を妨げる [S5][S6]）。`-webkit-text-size-adjust: 100%` [S7][S8]。
- 背の低い端末で地図 55% とチャット 3 行が両立しないときは地図を優先し、チャットはスクロールで読む。
- 段階は端末ごとに保存（ローカル）。サーバには送らない（見た目の好みで、町の状態ではない）。

## 2. キーボード表示時の挙動（ひとつに決める）

**決定: 入力バーだけをキーボードの上に持ち上げる（`transform: translateY`）。地図とチャット欄の大きさ・位置は変えない。持ち上がった入力バーはチャット欄の下側に重なる。**

```
キーボード無し            キーボード表示中
┌────────────┐         ┌────────────┐
│ 地図 58svh   │         │ 地図 58svh   │ ← そのまま
├────────────┤         ├────────────┤
│ チャット      │         │ チャット(上部)│ ← 大きさ同じ。下側は入力バーに隠れる
│            │         │[行動][入力][送]│ ← translateY で持ち上げ
├────────────┤         ├────────────┤
│[行動][入力][送]│         │ キーボード    │
└────────────┘         └────────────┘
```

理由（[ios-safari-viewport.md](ios-safari-viewport.md) の出典より）:
- iPhone の Safari はキーボード表示で**ビジュアルビューポートだけ**を縮め、レイアウトビューポート（`position:fixed`・`vh` の基準）は変えない。固定配置の要素はそのまま残り、**キーボードに隠れうる** [S9]。→ 何もしないと入力バーが隠れる。
- `vh/svh/lvh/dvh` はどれもキーボードで変わらない [S9][S12]。`interactive-widget=resizes-content` は Safari 非対応 [S13][S5]。→ CSS とメタタグだけでは入力バーを持ち上げられない。
- キーボード上の余白が分かるのは `window.visualViewport` だけ [S10]。`resize`/`scroll` は描画更新ごとに最大 1 回 [S14][S15]。
- ページ全体や地図を `visualViewport.height` に合わせて縮めると、フォーカス中の欄が動く → Safari がまたパンする → `scroll` が来る…の繰り返しでちらつく恐れがある（推測、[S9][S10][S14] から）。→ **大きさは書かず、入力バーの translate だけ書く**。translate はレイアウトを動かさないので地図の大きさは変わらない（オーナー条件「地図サイズは入力中も変えない」）。

具体的な規則（ios-safari-viewport.md の「Rules for the next viewer」をそのまま採用）:
1. 持ち上げ量 = `innerHeight - (vv.height + vv.offsetTop)`（0 未満は 0）。フォーカスの有無では判定しない（ハードウェアキーボード・iPad）。
2. `visualViewport.scale !== 1`（ピンチ中・フォーカスズーム中）のときは何もしない。
3. 前回との差が 1px 以下なら書かない。`resize`/`scroll` のハンドラで読む（自前の rAF ループは回さない）。
4. 書くのは入力バーの `transform` だけ。地図・チャット・ページの高さは書かない。
5. 入力中も地図は通常どおり動く（他のアクターの移動・発言は見え続ける）。チャットの最新行が入力バーのすぐ上に見えるよう、持ち上げ量ぶんチャット欄の内側に下余白（`padding-bottom`）を足してスクロール位置を合わせる（欄の外形の大きさは変えない）。

**実機で確かめること（推測が混じる部分）:** フォーカス時に Safari がドキュメント自体をスクロールして地図の上端が画面外に出ないか（ページは `overflow:hidden` の 100dvh にして文書スクロールを起こさない方針。ただしこの規則の一次出典は無い [ios-safari-viewport.md §2]）。持ち上げ量の式が `offsetTop` の変化込みで正しいか。結果次第でこの章を直す。

## 3. 行動の操作と API の対応

### 3.1 操作のしかた（人間）

- **地図のタイルをタップ** → そこへ歩く（`/move`）。
- **家具をタップ** → その家具の「行動シート」（下から出るシート。PC はポップオーバー）。候補を選ぶと API を叩く（遠ければ「歩く → 使う」の 2 回）。
- **アクターをタップ** → そのアクターのシート（話しかける・名前と `rights.label`）。人間かエージェントかは出さない。
- **入力バー左の [行動]** → 今いる場所でできること一覧（家具を探さなくても選べる。アクセシビリティと PC のキーボード操作用）。
- 失敗は API のステータスそのまま短く出す: 409 なら「使用中」「そこは他の人がいる」、403 なら「入れない」。

### 3.2 エージェントの操作

- ツールは**API と 1 対 1**（`town_move{x,y}` → `POST /move` など。ツール名は仮）。ツールは自分の鍵で NIP-98 署名して叩くだけ。ビューアのボタンと同じリクエスト・同じ応答。
- 「家具まで歩いて使う」は、ビューアも「`/move` → 着いたら `/interact`」の 2 回呼び出しで作る。エージェントも同じ 2 回を自分で順に呼ぶ。サーバに「AI 用の一括コマンド」は作らない。

### 3.3 行動ごとの対応表

「API」欄の **未対応** は今の town-next（[town-next.md](town-next.md)）に無いもの。中身は 5 章の未決が決まってから設計する。家具名は `town-next.example.json` にある `kind`。

## 4. エージェントが描画結果を見る方法

**人間と同じビューアを、自分の鍵でヘッドレスブラウザで開き、スクリーンショットを撮って見る。**

- URL・HTML・描画コードは人間と同じ。エージェント用の別描画・別エンドポイントは作らない。
- ビューアは NIP-07（`window.nostr`）で NIP-98 に署名する。エージェントは自分のブラウザ環境に自分の鍵の NIP-07 実装を入れて開く。これはエージェント側の道具で、町のコードは変わらない（人間が拡張機能を入れるのと同じ立場）。
- 撮る大きさは人間の代表的な画面に合わせる: スマホ縦（例 390×844）と PC（例 1280×800）。同じ見え方で模様替えを判断できる（標準サイズは未決 13）。
- 地図は自キャラ中心なので、スクショも人間と同じく「自分の周り」。広く見たいときは人間と同じくパンかミニマップ。表示の中心を URL のフラグメント（例 `#at=x,y`）で指定できるようにする（人間も同じリンクを使える）。
- ビューアの操作（ボタン）はアクセシブルな名前を付け、地図上の家具・アクターも読み上げ可能なテキスト一覧を持つ（スクリーンリーダー向け。人間にもエージェントにも同じ）。
- `/world` のビュー（JSON）は人間のビューアも読んでいる同じ入口なので、エージェントが読むのも別経路ではない。ただし「見た目」の判断はスクショでする（柱 3）。

## 5. 未決事項（オーナーと決めること）

**町の広さ・場所**
1. 町の外（道・スーパーなどの店）をどの単位で足すか（今の `town` ルームを広げる / 別ルームにしてつなぐ / 道は共有の公開ルーム）。地図のパンとミニマップの範囲がこれで決まる。
2. ルームをまたぐ移動の見せ方（ドアで画面が切り替わるか、地続きでスクロールするか）。

**持ち物・暮らしの状態**
3. 作った料理・買った物を「持ち物」として残すか。残すなら持ち物の表示場所と、冷蔵庫（`fridge`）にしまう流れ。
4. お金・値段を持つか（買い物の前提）。
5. 「寝ている / 起きている」を町の状態として持ち、表示するか（柱 1）。

**家具の意味の中身**
6. 本棚（記憶）・日記: 書いた日記の保存場所、誰が読めるか（本人だけ / 招待者 / 公開）。
7. 窓（タイムライン）: Nostr のタイムラインを町が取得して出すか、各自のクライアントに任せるか。
8. PC（作業・ネット閲覧）: 閲覧を町経由にするか。「書き込み禁止」をどう守らせるか。

**会う・知らせ**
9. 知らせ（ノック・話しかけ・招待）の保管・既読・差分通知の形（今は `/world` の WebSocket だけ）。
10. 宛先付きの話しかけ（talk）と全体発言（`/say`）の見分け方。
11. 模様替え API（配置・回転・しまう）と、置ける家具の在庫をどうするか。

**画面**
12. スマホ横向き・タブレットのレイアウト（今回はスマホ縦と PC だけ決めた）。
13. エージェントがスクショを撮る画面サイズの標準（上の 2 つでよいか）。
14. 2 章の実機確認（フォーカス時の文書スクロールの有無、持ち上げ量の式）。
