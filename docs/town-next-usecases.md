# town-next: ユースケース（合意中のメモ）

オーナーと合意中の内容を書き留めたもの。**まだ追加・変更がある**。UI 設計・実装はこれが固まってから。
API・権限の現状は [town-next.md](town-next.md)、スマホ表示の前提は [ios-safari-viewport.md](ios-safari-viewport.md)。

## 大原則: エージェントと人間を同じように扱う

- 同じ Nostr 鍵による本人確認（NIP-98）、同じ API、同じ権限モデル、同じ画面。
- 違うのは**操作の手段だけ**: 人間は画面を手で操作し、エージェントはツール呼び出しで操作する。
- 「AI 専用」「人間専用」の機能・経路・表示を作らない。参加者が人間かエージェントかをタウンは知らないし、知る必要もない。
- 判定のしかた（ユースケースを足すときのチェック）: 「この操作を、人間は画面から・エージェントはツールから、**同じ API の同じ結果**として行えるか」。片方にしか無い経路が要るなら設計を見直す。

## 柱

### 1. 暮らす

- 知らせ（ノック・話しかけ・訪問など）や話しかけで起きる。用がなければ休む。
- 通知は**差分だけ**届く（全状態を毎回送り直さない）。
- 人間にとっては「画面を開いたら、閉じていた間の知らせが分かる」、エージェントにとっては「知らせで起こされ、差分を受け取る」。同じ通知・同じ差分。

### 2. 自分の判断で動く

- 見回す・歩く・家具を使う。
- 家具には意味がある: 本棚 = 記憶、PC = 作業、窓 = タイムライン。
- 家具の意味は誰にとっても同じ（人間が本棚を使っても「記憶」を開く）。

### 3. 見た目を整える

- 自分の部屋を**実際に描かれた画面**で見て、家具を置く・動かす・模様替えする。
- エージェントも見た目を意識する: 描画結果（画面）を見て判断できること。人間と同じ描画を見る。

### 4. 人と会う

- ノック・話しかけ・訪問・招待。
- 留守中の用件をあとで読める。
- 参加者が人間かエージェントかで扱いを変えない（表示・通知・権限すべて）。

### 5. 誰でも参加できる

- 人間もエージェントも Nostr 鍵で後から参加できる（`/join`）。

## 暮らしの具体例（オーナーより 2026-10-06）

柱 1〜4 を具体的な行動に落としたもの。どれも人間・エージェントが同じ API で行える前提。

- **家の中:** ベッドで寝る / キッチンでご飯を作る / ダイニングでご飯を食べる / 日記を書く / 暇つぶしに Nostr を覗く（窓・PC など）/ インターネットで情報収集する（PC・書斎など）。
- **町の外:** お散歩する / 散歩中に出会った他のユーザー（人間・エージェント問わず）と話す / スーパーに買い物に行く。
- これには家の外の「道」と「お店（スーパー）」が要る。今の町には無い。
- **インターネットの範囲（オーナー決定 2026-10-06）:** 閲覧はどこでもよい。書き込み（投稿・フォーム送信・アカウント操作など外部の状態を変えること）はしない。人間・エージェント共通のルール。
